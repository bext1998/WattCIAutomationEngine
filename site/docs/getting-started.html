開始使用

快速開始

在 Windows 專案根目錄建立 watt.yaml，先檢查設定與環境，再執行你的第一個 pipeline。

使用指南，非契約規格本頁只說明操作方式；watt.yaml 的完整格式、結果檔格式與結束碼規則，以 docs/spec.md 為準。

1. 安裝 watt.exe

從 GitHub Releases 下載對應版本的 watt.exe。

什麼是 PATH？在終端機打指令時，Windows 只會去幾個固定的資料夾裡找對應的程式，這份清單就叫 PATH。剛下載的 watt.exe 不在這份清單裡，所以直接打 watt 會出現「不是內部或外部命令」的錯誤；把它所在的資料夾加進 PATH，之後在任何地方打 watt 就能直接執行。

  1. 找個固定的地方放 watt.exe，例如新建 C:\Tools\watt\ 資料夾
  2. 按 Windows 鍵，搜尋「編輯系統環境變數」並打開，點「環境變數(N)...」
  3. 在「使用者變數」區塊找到 Path，選起來後點「編輯」→「新增」，貼上剛才那個資料夾的完整路徑（例如 C:\Tools\watt），一路按確定關閉視窗
  4. 重新開一個新的 PowerShell 視窗（開著的舊視窗不會生效，一定要開新的才讀得到剛才的設定）

完成後，確認指令可用：

PowerShell
watt --version
watt --help

2. 建立第一份 pipeline

在要驗證的專案根目錄建立 watt.yaml。以下範例會執行 Go 測試；請替換成你的專案實際指令。

watt.yaml
version: 1

pipelines:
  default:
    steps:
      - name: Test
        exec: go
        args: ["test", "./..."]

3. 先檢查，再執行

watt check 只驗證 YAML 結構與欄位規則，不會啟動任何 step。加上 --env 後，Watt 也會確認 pipeline 使用的 command 與 shell 是否可在 PATH 找到。

PowerShell
watt check --env
watt run

執行成功後，Watt 會在專案的 .watt/result.json 寫入結果。需要挑選其他具名 pipeline 時，使用 watt run <名稱>。

提示：watt check 不會寫入 result.json；只有通過載入與靜態驗證後的 watt run 才會盡力產生結果檔。

下一步

繼續閱讀 watt.yaml Pipeline 撰寫手冊，加入更多 steps、工作目錄或專案專屬環境變數。
